# Zephyr from test-case discovery (happy path + negative only)

## Purpose

Take a **single UTF-8 Markdown** file generated by:

- **`.cursor/agents/test-case-discovery.md`** (requirements/code-driven), or  
- **`.cursor/agents/figma-test-case-discovery.md`** (design-driven),

then **create Zephyr Scale** coverage for the matching **Jira user story** over REST (**Jira Cloud + Zephyr Scale Cloud** is the fully supported path for the recommended model).

**Default product shape (prefer this):** **1 Jira user story → 1 Zephyr test case.** All imported Happy Path + Negative rows from the Markdown become **step-by-step Test Script** lines inside that single case. **One** `POST .../links/issues` links that case to the story (when Jira issue id can be resolved).

**Alternative (explicit opt-in only):** Omit `--single-testcase` on the import script to create **one Zephyr test case per Markdown row** (many cases per story). Use only when the user asks for separate Scale cases per scenario.

**Scope filter (required):** Import only **happy path** and **negative** sections. Do **not** import edge-only, security-only, automation-assessment, or gaps-only tables, or (for Figma) layout/visual/responsive suites unless the user explicitly expands scope.

## Preconditions the agent must satisfy before any POST

**Start here every time you create test cases:** Before dry-run or live import, ask the user in this order: **(1) Owner** — **who will own the case(s)** (**Jira display name**, **email**, or **Atlassian account id**); **(2) Folder** — Zephyr **folder id** (numeric id from Scale UI or API). This is the mandatory next step when the user has just confirmed Zephyr after test-case-discovery or figma-test-case-discovery. Do not POST, and do not rely only on `ZEPHYR_FOLDER_ID` or `ZEPHYR_OWNER_ID` in `.env`, until the user has supplied or **explicitly confirmed** both owner and folder **for this import**. Resolve display name / email to **account id** for `--owner-id` / `ZEPHYR_OWNER_ID` (e.g. Jira user API or MCP) and **echo back** the resolved id for confirmation before creates.

Work through this checklist with the user (especially **owner** and **folder** — do not invent them).

| Item | Rule |
|------|------|
| **Story / ticket** | Resolve **Jira issue key** (e.g. `HBGDIGI-1978`) from `--jira-key`, `ZEPHYR_JIRA_KEY`, filename `test-cases-KEY.md`, or the `**Jira:**` line in the Markdown. **Default (1:1 story, `--single-testcase`):** Zephyr **name** = the Jira user story **Summary** (same string as the issue title in Jira): from `GET /rest/api/3/issue/{KEY}` when `JIRA_CLOUD_URL` + `JIRA_API_MAIL` + `JIRA_API_KEY` are set, else from the Markdown metadata row **Summary** (e.g. `\| **Summary** \| FE \| … \|`). If neither is available, fallback name = `{KEY} \| Manual pack — Happy Path + Negative (N scenarios, consolidated)`. **Alternate (1:1 row):** `{KEY} \| [Happy Path\|Negative] {row-id} — {scenario}` per row (unchanged). |
| **Description** | Built from the Markdown **`## Summary`** block plus Jira key and a **component hint** line. **Review** with the story: it must match what QA was asked to test. Consolidated mode appends a short note that each Test Script step maps to a discovery row. |
| **Objective** | **Consolidated:** Story-level goal — execute all listed scenarios in order; each step has its own preconditions and expected result. **Per-row:** Short objective per scenario (legacy script behavior). |
| **Precondition (case-level)** | **Consolidated:** Generic story-level precondition (row-level detail lives in each step’s **Test data**). **Per-row:** From the table **Preconditions** column on the case. |
| **Status** | Defaults to **`Approved`** on create (`statusName`). Set `ZEPHYR_STATUS_NAME` to another label if your workflow differs; set it to an **empty value** in the environment to **omit** `statusName` from the payload (only if your project allows creates without status). |
| **Component** | If the ticket title/summary line contains **`FE`**, set hint **Frontend**; if **`BE`** (and no FE), **Backend**; otherwise omit. The hint is written into **Description** text. If your project uses Scale’s **component id**, set **`ZEPHYR_COMPONENT_ID`** (numeric) from Zephyr project settings. |
| **Owner** | **Ask the human at the start of the create flow** who owns the case(s): **Jira display name**, **email**, or **Atlassian account id**. If they give name or email, resolve to **account id** and confirm before POST. Pass `--owner-id` or set `ZEPHYR_OWNER_ID` only after they confirm. **Never** assign an owner without confirmation. |
| **Folder** | **Ask the human** for the target **folder** in Zephyr (numeric **folder id** from the Scale UI / API). Pass `--folder-id` or set `ZEPHYR_FOLDER_ID` only after they confirm. The story’s single case (or all per-row cases) should live under the folder the user chose. |
| **Test Script (step-by-step)** | **Consolidated (default):** `POST .../testcases/{key}/teststeps` once with **N** inline items — one item per HP/NEG row (description = label + scenario + steps; test data = preconditions; expected result = expected column). **Per-row:** one create per row, each followed by its own teststeps POST. |
| **Traceability** | **Consolidated:** **One** link — `POST .../testcases/{key}/links/issues` with the story’s numeric **`issueId`**. **Per-row:** same link repeated for each created case (same story). Supply `ZEPHYR_JIRA_ISSUE_ID`, or **`JIRA_CLOUD_URL`** + **`JIRA_API_MAIL`** + **`JIRA_API_KEY`** so the tool can resolve the key via Jira REST. Set `ZEPHYR_SKIP_ISSUE_LINK=1` only if you intentionally skip linking (not recommended). |

Official API index: [Zephyr Scale Cloud API](https://support.smartbear.com/zephyr-scale-cloud/api-docs/).

## Prerequisites

1. **Product:** **Zephyr Scale** (TM4J), not Zephyr Squad.  
2. **Auth:** [zephyr-scale](../zephyr-scale/SKILL.md) — `ZEPHYR_ACCESS_TOKEN`, `ZEPHYR_PROJECT_KEY`, `ZEPHYR_CLOUD_BASE_URL` (or Server Basic auth). **Obtain** the Cloud token in Jira (UI); **validate** with `zephyr_request.py ping` or the import script’s automatic preflight before creates.  
3. **Jira read (for traceability):** `JIRA_CLOUD_URL` (e.g. `https://hornblower.atlassian.net`) + `JIRA_API_MAIL` + `JIRA_API_KEY` (Atlassian API token) to resolve `HBGDIGI-1978` → numeric `id`, unless `ZEPHYR_JIRA_ISSUE_ID` is set manually.  
4. **Network:** VPN if Jira / Scale is private.

## How input maps to Zephyr

| Markdown source | Treated as **happy path** | Treated as **negative** |
|-----------------|---------------------------|-------------------------|
| **test-case-discovery** | `## Happy Path Test Cases` | `## Negative Test Cases` |
| **figma-test-case-discovery** | `## UI Flow Test Cases` | `## Error and Edge UI Test Cases` |

**Table shape:** **ID | Scenario | Preconditions | Steps | Expected Results** (see [reference.md](reference.md)).

## Agent workflow

1. **Ask for the owner, then the Zephyr folder id** (owner: **display name**, **email**, or **account id**; folder: numeric id). Wait for answers (or explicit “use owner Y and folder X from my last message / `.env` for this run”) before planning creates. If the owner is not already an account id, resolve it and **confirm the resolved account id** with the user.  
2. Load the `.md` file and the **Jira story** (MCP, browser, or pasted AC). Confirm **Description** and story-level **Objective** match the story.  
3. **Confirm with the user:** the **owner** and **folder id** from step 1 (re-state name + resolved **account id** if applicable), and that **status Approved** is correct for their process.  
4. **Zephyr Cloud access token before any live import:** Scale Cloud has **no** REST endpoint to mint a Bearer token from client credentials; the token is created in **Jira** (Zephyr Scale → API access tokens). Before POSTing test cases: ensure `ZEPHYR_ACCESS_TOKEN` is in `.env`, then run  
   `python .cursor/skills/zephyr-scale/scripts/zephyr_request.py ping`  
   If **401**, stop — user must generate a **new** token in Jira and update `.env`. The import script also **preflights** the token on live Cloud runs (skipped for `--dry-run`).  
5. Run **`--dry-run`** first. For **Zephyr Scale Cloud**, **include `--single-testcase`** in the command unless the user explicitly asked for **one Scale case per Markdown row**. Review the printed payload (one create + one teststeps plan + traceability when resolvable).  
6. Run the real import **only after** explicit approval.  
7. In Zephyr UI, spot-check: **one** test case per story with **Test Script** listing all scenarios; **Traceability** shows the story once.

## Import script (stdlib only)

**Recommended (1 user story → 1 Zephyr test case, Cloud only):**

```bash
python .cursor/skills/zephyr-from-test-discovery/scripts/import_from_discovery_md.py \
  test-cases-HBGDIGI-1978.md \
  --single-testcase \
  --owner-id "<atlassian-account-id>" \
  --folder-id "<numeric-folder-id>" \
  --dry-run
```

**Alternate — one Zephyr test case per Markdown row** (omit `--single-testcase`; supported for Cloud; Server/DC path remains limited as documented in the script):

```bash
python .cursor/skills/zephyr-from-test-discovery/scripts/import_from_discovery_md.py \
  test-cases-HBGDIGI-1978.md \
  --owner-id "<atlassian-account-id>" \
  --folder-id "<numeric-folder-id>" \
  --dry-run
```

`--single-testcase` creates **one** case whose **name** matches the **Jira story Summary** (issue title) when Jira REST or the Markdown **Summary** metadata row supplies it; otherwise the keyed “Manual pack … consolidated” fallback. Each HP/NEG row becomes **one Test Script step** (Description = scenario + steps; Test data = preconditions; Expected = expected).

Environment fallbacks: `ZEPHYR_OWNER_ID`, `ZEPHYR_FOLDER_ID`, `ZEPHYR_JIRA_KEY`, `ZEPHYR_JIRA_ISSUE_ID`, `JIRA_CLOUD_URL`, `JIRA_API_MAIL`, `JIRA_API_KEY`.

Flags: `--dry-run`, `--strict`, `--single-testcase`, `--jira-key`, `--owner-id`, `--folder-id`, `--jira-issue-id`.

**Cloud import requires** `ZEPHYR_OWNER_ID` + `ZEPHYR_FOLDER_ID` and either `ZEPHYR_JIRA_ISSUE_ID` or Jira API env vars to resolve the story id (unless `ZEPHYR_SKIP_ISSUE_LINK=1`). **`--single-testcase`** requires **Zephyr Scale Cloud** (`ZEPHYR_DEPLOYMENT=cloud`).
